Cyan：训练故障诊断与受控修复

Cyan 是一个本地双进程系统。确定性的训练监督、证据选择和修复验证包围一个只执行受限工具调用的 Agent 内核。

进程与所有权

cyan TUI / VS Code→ TCP loopback / NDJSON / JSON-RPC 2.0 cyan-core

training.jobs 独占训练进程组和持久化日志；training.incidents 独占故障状态、证据、提案和验证；agent 只负责显式工具驱动的 LLM 运行；service 负责协议和传输。

一次故障的闭环

/monitor 预览命令→ JobSupervisor→ Failure Capsule→ Evidence Selector→ 六个受限工具的只读 Agent→ Diagnosis / Proposal→ 人工批准→ PatchService→ Smoke / 原命令重跑

原训练命令的退出码始终是最终成功依据。Smoke 是可选的前置验证；补丁应用、重试和恢复由 Incident Coordinator 控制。

模块边界

src/cyan/
├── agent/       # 最小 LLM → tool → observe → stop 内核
├── training/    # jobs、processes、incidents 与验证闭环
├── service/     # daemon、协议、RPC 与 TCP 传输
├── cli/         # cyan 与 cyan core start/stop
├── tui/         # /monitor、/start、/jobs、/incident、/help
└── config.py    # 三个领域共享配置

Incident profile 固定注册 read_file、list_dir、search_text、read_job_log、submit_diagnosis、propose_patch。没有写文件、Shell 或任意扩展工具。

组件约束
Evidence Selector v1纯函数、分块扫描不可变日志、固定优先级、最多 32 KiB；不调用 LLM、不读源码、不缓存。
Incident Context每轮只放当前 Capsule、选择的证据、当前指令、上一轮有限结果和最新验证结果；总输入最多 128 KiB。
AgentRunner只接受显式 RunProfile 和工具；超出预算的工具结果替换为结构化预算事件，不发送已知超限请求。

持久化

~/.cyan/jobs/<job_id>/incidents/<incident_id>/
├── incident.json
├── proposal.diff                 # 有提案时才存在
├── smoke.stdout.log              # 运行 Smoke 时才存在
├── smoke.stderr.log
└── runs/<run_id>/
    ├── run.json
    └── events.jsonl

incident.json 是当前快照；run.json 是单轮有限记录；events.jsonl 只保存摘要事件，用于重连回放和运行评测。完整训练日志仍属于 Job Attempt，不复制进 Incident。

协议与公开表面

Wire Protocol v2 保留启动、停止、订阅、Job、Incident、Run、Step、Tool 和 LLM 事件，并提供 incident.follow_up。TUI 是正常用户的唯一入口；公开命令为 cyan、cyan --version、cyan core start [--json]、cyan core stop 和内部的 cyan-core。
